Fresh online MDB research, 2026-11-01

Scope: fresh external search and original published specifications. No previous MediaMuster documentation, evidence, tests, or fixtures were read or used. The independently cloned pymdb source was freshly discovered online. The comparison corpus came from the root agent's new filesystem manifest. Online coverage is broad and documented, not a claim that every document on the entire web has been found.

Primary Avid database semantics
https://kb.avid.com/pkb/articles/en_US/Knowledge/en262645
Avid states that PMR caches map file MOBs to associated media files and determine online status; MDB supplies information displayed in Media Tool and used for relinking. Editors maintain internal caches, and on-disk databases can lag or fail to update. This means an MDB parser can accurately report recorded metadata while a media file is absent or newer. Agreement between MDB readers alone cannot prove current physical-media truth. Avid also distinguishes per-directory editor-managed databases from a workspace-level MDB Manager database in MediaManager environments.

https://kb.avid.com/pkb/articles/en_US/How_To/How-to-find-clips-in-the-Media-Tool
The official Media Tool supports distinct views for master clips, linked master clips, rendered-effect precomputes, title/matte-key precomputes, and media files. Counts are comparable only when the view and row unit match.

https://kb.avid.com/pkb/articles/en_US/Troubleshooting/Refreshing-Media-Databases
Avid explains that databases identify and locate stored media and can be rebuilt from media. This research did not delete or regenerate any user's database.

https://resources.avid.com/SupportFiles/attach/Mcwnew70.pdf
Avid's original Media/Film Composer release7 guide calls the media database a catalogue of master clips and precomputes and distinguishes it from PMR file-to-ID cache. This is historical behavior, not a current byte-format specification.

Original OMF specifications (Avid-authored, mirrored/archived)
https://web.archive.org/web/20030809131248id_/http://www.peakoverload.com:80/Downloads/omfspec10.pdf
OMF1.0 acquired as 507102-byte archived response containing an initial208-byte FTP header. Extracted valid506894-byte PDF,124 pages, retained as omfspec10.pdf; original response retained as omfspec10.html. Relevant printed pages50,66,81,91-92: component edit rate expresses edit units per second; group length uses edit units; file descriptor sample rate is native media rate; ExactEditRate stores four-byte numerator and denominator; legacy UID is96 bits; TrackKind1 is picture and2 sound. UsageCode values are registered/private, so the spec does not establish modern Avid's7/9/1/14 meanings. Private JPED/PCMA classes and attributes are not fully documented here.

https://www.cubase.it/wp/wp-content/uploads/2014/12/omfspec21.pdf
OMF2.1 acquired,282 pages. The class dictionary and inheritance model allow private subclasses. Printedp132 describes Digital Image Descriptor and CDCI/RGBA descendants as image media. AppendixD,p237 explains that OMF2 removed the OMF1 ObjectSpine, replaced TRKG/TRAK and removed ATTR/ATTB; therefore OMF2 field semantics must not be blindly transplanted onto the OMF1-based MDB variant. Printedp206 distinguishes timecode FPS and drop-frame state; descriptor sampling and timecode numbering are separate concepts.

Original Bento specification (Apple-authored, archived)
https://web.archive.org/web/20120906101250id_/http://info.wgbh.org/upf/pdfs/BentoSpec1_0d5.pdf
Acquired valid758639-byte PDF,106 pages. Revision1.0d5 describes a content-neutral object/property/type container with terminal label, TOC, segmented values and immediate-value optimization. Its rewritten format chapter describes compressed TOCs and a block-size label field, while the freshly found MDBs use legacy fixed24-byte TOCs with II byte-order field. The published revision is foundational but is not by itself a complete literal specification for these MDBs' private legacy variant.

Original MDVx author documentation
https://djfio.com/mdv/
https://djfio.com/data/products.json
https://djfio.com/assets/files/MDVx-theManual.pdf
Fresh manual acquired648961 bytes,9 pages, versionb3153,2019. It defines Rate as video bitrate or audio sample rate. Its three user-facing Kind categories are captured/default, precompute, imported; these are a different concept from audio/video media kind. Other implementation, freshly discovered
https://github.com/lawson-tanner/pymdb
https://pypi.org/project/python-mdb/
https://pythonmdb.readthedocs.io/en/latest/api/file.html
Cloned commit04380153a98580b7097de30520ed5a05005aaf2d, MIT, version0.1.0, published2026-08-22. Source independently decodes legacy Bento and preserves typed OMF objects. Its live-mob list uses HEAD.ObjectSpine; all-mob enumeration includes retained deleted entries. Its class dictionary handling recognizes subclass inheritance. Candidate limitations directly found in source/runtime: strings decode as UTF-8 replacement, corrupting MacRoman _PJ; legacy UIDs are fixed-little-endian in convenience classes; several validation rules are sample-derived. It is not an unquestioned oracle.

https://deck2omf.sourceforge.net/
The original Deck2OMF author describes independent Bento-compatible TOC dumping and notes variation in the Bento format used by OMF. Useful independent container interpretation, not documentation for private Avid MDB attributes.

Independent confirmation of JPED classification issue
jped-class-hierarchy.json records the current supporting MDB's own CLSD objects70579→70578→70577→70576 declaring JPED→CDCI→DIDD→MDFL. The file contains30 JPED descriptors. The documented meaning of DIDD/CDCI is image/video. Thus Bella returning Unknown kind for these30 native JPED files is under-classification despite preserving raster/codec/depth. A whitelist fix can add JPED; the general improvement is respecting the file-declared class hierarchy where safe. Public source https://pythonmdb.readthedocs.io/en/latest/_modules/mdb/objects/descriptors.html independently uses JPEGDescriptor(CDCIDescriptor), but the primary current file's declaration is the decisive evidence.

Limitations
The search found no complete publicly maintained byte-level specification of modern private MDB classes and attributes. Public OMF/Bento standards establish the container/model and selected base fields; current native binaries and raw fresh files remain necessary to establish private field precedence and modern variants. No claim is made that every MDB implementation is equivalent, that matching this finite corpus proves universal correctness, or that every online page was exhausted.
