Reproducible MDVx execution
prepare_mdvx.py extracts the arm64 slice to a temporary COPY, changes Mach-O filetype MH_EXECUTE to MH_BUNDLE and clears MH_PIE, then ad-hoc signs the COPY. The installed original is untouched. mdvx_probe.m dlopens that copy and calls original MDVxOMFI methods. This executes MDVx's original parsing machine code, not a replacement parser or a guessed clone. No PMR data or previous fixtures are supplied.
Original openFile:withIndicator: calls NSData dataWithContentsOfURL:; no write path is called. Each of the 13 fresh corpus inputs ran in its own subprocess, timeout 90 seconds. SHA256 was checked before and after every run: all 13 unchanged. runtime/index.json contains exact paths, hashes, exit status and native return values. No timeout, exception or process crash occurred.

MDVx implementation lessons
The native parser hardcodes numeric property IDs for extraction; runtime dictionaries label inspection data but do not make these extraction routes schema-independent.
OMFiTOCReader02 is a log-only stub. openFile returns false for that version path.
pDataFor permits index == TOCItemsCount (off-by-one); unbounded object-property scans rely on a following object sentinel. These are unsuitable safety patterns to copy.
UIDtoBentoObj stores and compares only eight bytes. Legacy 12-byte IDs use bytes4..11; full32 IDs use bytes16..23 in native lookup. Preserve fuller identity in the new parser. This corpus does not contain a live collision demonstrating a runtime loss, so do not report a measured live collision.
getProjectAttributeForObjectAt checks the '_PJ' prefix and does not provide Media Composer's PROJNAME fallback. getProjectNameForObjAt follows source clips to source mobs and can overwrite the previously found project as it traverses further source IDs. A deterministic selection policy and conflict reporting are preferable to copying last-write behavior.

Concrete Media Composer rules
1. CMGetProjectName checks '_PJ' first, then 'PROJNAME'. The raw disassembly supplies the argument that Hopper occasionally omits from the first virtual call.
2. JPED is an image descriptor. Its IsInstanceOf fallback calls omf2DIDD::IsInstanceOf (0x4ebbfc); its default constructor calls omf2CDCI::omf2CDCI (0x4ebd34). A parser classifying JPED as unknown while accepting comparable DIDD/CDCI as video is missing this picture-descriptor family.
3. RationalFromExactEditRate recognizes internal decimal 23976*k*10^-3 and 2997*k*10^-2 representations, then constructs (24000*k)/1001 and (30000*k)/1001 respectively (0x258318..0x258340). This proves an internal Avid conversion policy. It is NOT, by itself, proof that every arbitrary MDB rational must be normalized. Keep stored rate and canonical timing interpretation distinct and verify the path from deserialized MDB rate to timing display.
4. LocalMDB uses omfiHPDomain to read separate physical/source and logical/composition mob sets; loading raw objects without the live graph/domain distinction is not equivalent to loading the MDB.
