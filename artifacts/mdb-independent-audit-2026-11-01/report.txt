Fresh independent MDB parser audit and scope reassessment
1 November 2026

Bella remains the preferred base for the agreed MDB contract on the checked native corpus. Its catalogue and direct project selection are sound in those comparisons, and the measured parser workload is faster and smaller than current OldScanner's richer observation graph. The original audit incorrectly promoted deliberate scope reductions into improvement work. The user subsequently approved JPED Video classification alone; that change is complete and verified on all 30 native JPED records. Extra result fields, per-loop cancellation, generic provenance machinery, automatic class-hierarchy expansion and additional MDB formats are not default corrective work. The separate authored damaged-input audit retains three open qualification findings; it must not be confused with the successful native-corpus comparison.

Accuracy of current implementations

Bella and current OldScanner return exactly the same file and master identities and direct master relationships. Their common semantic values agree for descriptor lengths, sample rates, audio display clocks, all 1,513 audio frequencies, all 2,515 semantic bit depths, raster dimensions, explicitly recorded coding labels, master names, bins, types and precompute categories. All 232 comparisons where Bella establishes recorded drop-frame state also agree. Optional-detail mode changes only the intended precompute category output.

An independently discovered Python implementation, pymdb commit 04380153a98580b7097de30520ed5a05005aaf2d, independently confirms live catalogue membership, descriptor classes, raw lengths and rate pairs, master names/types/bins, and file-to-master links. All 2,156 file and 1,236 master full 32-byte identities match exactly. The remaining 359 file and 184 master legacy 12-byte identities match canonical material aliases. pymdb is useful structural corroboration; its UTF8 replacement decoding corrupts MacRoman text, so its convenience strings are not an oracle.

The original snapshot had two meaningful differences between Bella and current OldScanner. After the approved JPED change, only the 86 Project differences remain in the common semantic comparison:

1. JPED Kind: separately approved expansion, now implemented.

All 30 occur in the installed SupportingFiles database. The original Bella snapshot retained descriptorClass=JPED and valid length/raster/codec/depth but returned MdbKind::Unknown; OldScanner returned video. The fresh MDB itself declares JPED -> CDCI -> DIDD -> MDFL in CLSD objects 70579, 70578, 70577 and 70576, corroborated by Media Composer. Unknown was consistent with the original deliberately restricted six-class Kind contract. The user's subsequent 1 November instruction authorized adding JPED to Video. Both detail modes now return Video for exactly those 30 records; every other report value remains unchanged across all 13 original inputs. Current Kind disagreements with OldScanner are zero.

The current fixed map is PCMA/AIFD/WAVD -> Audio and CDCI/RGBA/MPGI/JPED -> Video. MPGA, WAVE, TIFD and automatic subclass/inheritance classification remain outside this Kind mapping. Reusing a broader helper would silently expand it and is not authorized by the JPED instruction. Independently qualified metadata remains usable when Kind is Unknown.

2. Bella correctly retains 86 direct file-owned project values that current OldScanner leaves blank.

The values are PeleSympProj (3), BLOCK_1729_PS_DG (34), and BLOCK_1730_PB_PA (49). All 86 have their own direct _PJ attribute. Each immediate upstream source records a different project; its linked master has no own project. Bella returns the file's own _PJ with OwnFile selection. Current OldScanner combines different owners' candidates and withholds a value because they conflict. Independent raw attribute/source/master traces are in online/project-validation.json. This is a concrete Bella accuracy benefit, not a guess that a nonempty value is preferable.

MDVx comparison

The installed MDVx is version 0.2 build 4073. Its original arm64 MDB methods were invoked through a fresh harness: a separate executable copy was converted to a loadable Mach-O bundle and ad hoc signed; the installed executable was untouched. Input loading uses NSData read-only access. This tests original MDB code, not a reimplementation, but it is not a full PMR-assisted GUI scan.

MDVx opens all seven Avid inputs and rejects all six unrelated LMDB inputs. Its native live composition counts total 1,420. All 2,515 file and 1,420 master identities join uniquely against its live HEAD-selected objects. All master names agree. All 1,002 comparable stored video FourCC/resolution-ID values agree. All 1,511 comparable PCMA audio frequencies agree. Available raw component widths/sample bits agree; raw width sentinels must not be compared directly to Bella's interpreted bit precision.

MDVx is less accurate for project text on this corpus. It returns zTe§t where the original MacRoman byte 0xA7 means zTeßt: 361 project values are affected (359 Shared MXF files and two Shared OMFI files). MDVx returns no project for another 108 files where Bella supplies one. The remaining 2,046 projects agree. These are original native getter results; no formatting-only dictionary/list mismatch is counted as a decoding error.

The native MDB summary interface does not provide an independent duration, raster or audio/video Kind oracle. MDVx also synthesizes _AUD and zero/default struct members in some cases; these are not recorded codec properties. Its manual's captured/imported/precompute Kind is a different concept from Bella's audio/video Kind. Never copy native output indiscriminately into the parser.

Binary reverse engineering

Genuine Hopper pseudocode exports were captured for 12 targeted MDVx MDB routines and 10 selected Media Composer routines, with supporting arm64 disassembly. This is targeted MDB reverse engineering, not a claim that both applications were completely decompiled. Some large functions have incomplete or register-level pseudocode; saved assembly is the reference in those cases.

MDVx exports cover opening, TOC1/TOC2, data bounds, text, project traversal, UID handling, compression and item enrichment. Its TOC2 route is a stub, so MDVx does not establish broad Bento2 support. Its compact identity comparison is not a reason to shorten Bella's full identity keys. A real file/master pair in EDIT/8646 shares eight material bytes while its complete IDs differ.

Media Composer is 26.8.0.58987. The inspected MDB-related implementation is principally libameLibrary.dylib, SHA256 659e3b6d07c9ae0d54f5741a153244e4a9c554d030c28e0cc7f4c73dba65ba22. Its CMGetProjectName at 0x282b9c uses _PJ before PROJNAME; JPED is in the digital-image class family; RationalFromExactEditRate at 0x258148 recognizes decimal aliases of 23.976 and 29.97 and produces 24000/1001 or 30000/1001 multiples for the internal ExactEditRate conversion.

That last rule is not proof that every arbitrary MDB rational must be rewritten. Preserve recorded numerator, denominator and type. Bella already preserves these and applies equivalent alias handling to numbering. Any duration/display adapter should carry the established ExactEditRate meaning forward instead of blindly treating every stored decimal as an ordinary rational. Media Composer's full Media Tool output was not used as a field-by-field runtime oracle.

Performance and robustness

Five alternating-order Release runs per database used isolated processes and count-only output, with warm file caches. Bella's median parse/extract time was 2.0 to 9.75 times faster than current OldScanner's read/project path. On EDIT/86452, Bella measured 103 ms and 113 MB peak RSS; OldScanner measured 869 ms and 978 MB. These compare the actual current API contracts: OldScanner retains a much richer raw observation graph. They are not a claim about identical-functionality implementations or full-application scan speed.

AddressSanitizer and UndefinedBehaviorSanitizer ran both current parsers against all 13 original inputs plus 136 new deterministic truncation/TOC/bit-mutation cases: 298 process runs with no sanitizer reports, crashes or timeouts. These fresh mutation cases were generated solely for this audit; passing them is bounded evidence, not proof of universal memory safety or semantic validity.

Agreed scope and remaining work

Completed: the separately approved JPED-only classification change. The rerun retains 2,515 file records and 1,420 masters, all input hashes are unchanged, and MDVx/independent-reader comparisons retain their previous results. Nine alternating-order runs per database measured aggregate median parse times of 243.8 ms before and 243.3 ms after; per-database changes were under 1% and median peak RSS did not increase. The affected generated-control test and 298 sanitizer executions passed. See ../mdb-jped-kind-2026-11-01/validation.json and benchmark-delta.json.

Withdrawn as default work: restore channels, recorded Source Path, source-container values and imported status as extra Bella results. The older API's counts (1,513 channels, 411 paths, 581 containers and 2,381 imported-status values) describe capabilities, not missing product requirements. Copland deliberately removed unused retained channel/container/imported row copies while allowing temporary facts needed for retained interpretation. Bella later explicitly excluded recorded Source Path extraction, selection, storage, display/search/export and reads solely for it. Physical File Path remains required.

Withdrawn: per-entry/object/link cancellation checks and chunked capture. On 30 October the user chose readAll with before/after checks and phase-only cancellation across two in-memory stages, explicitly declining loop polling and accepting that a current call/stage can finish first. That behavior is not an unmet responsiveness requirement. A missing agreed checkpoint or incorrect retained Cancel result would still be an in-scope bug; this native audit established neither.

Withdrawn: generic machine-readable per-field failure/source/explanation records or contributor histories. The agreed compact report uses ordinary owned values, field-specific machine-readable qualifications needed for validity/matching, and problemNotes with necessary source/owner/field context. Adding generic wrappers or a retained raw property graph would reverse that decision. Correcting a missing required qualification or inaccurate explanation remains in scope.

Deliberately deferred: Bento2/OMF2/IMA MDB variants, unknown versions and wider unapproved Kind classes. Truthful Unsupported/Unknown results under the agreed rules are not defects. The approved typed video ExactEditRate interpreter and duration formatter remain existing planned work; raw words/type must survive and literal Rational/audio-frequency values must not receive video aliases. This is not a newly discovered rate-parser defect.

Within scope: fix demonstrated violations of approved ownership, identities, typed reading, trusted shared foundations/local damage handling, required qualifications or diagnostic meaning. Measured removal of unnecessary copies/allocations/repeated work is also within scope if outputs, checks, lifetimes and approved cancellation boundaries are preserved. This fresh native-corpus audit did not establish another such parser defect or a specific remaining performance bottleneck.

Separate open authored-input findings: docs/reviews/2026-11-01-bella-mdb-review/VERDICT.md records class-inapplicable relationship edges/targets, counted null attribute slots and unqualified category track/component classes. All 28 retained controls were rerun against the current JPED source during this documentation update and reproduced their earlier outputs. These are current in-scope qualification findings, not the withdrawn feature/API recommendations, and no further production fix is made here. Their corpus is separate from the seven fresh native databases.

The governing scope reassessment and duplicate-test cleanup receipts are in ../mdb-scope-reassessment-2026-11-01/. Three duplicate executed cases were removed: the standalone zero-length case is covered more thoroughly in both byte orders, and two broken-JUNK audio-summary rows duplicate stronger framing assertions. The generated-control run passed 155 Qt cases including setup/cleanup; checked-in fixture selectors were not executed and no new full-suite total is claimed. JPED Video, MPGA Unknown and unsupported-format rejection controls remain. Historical raw observations and source hashes remain frozen at their recorded revisions.

Avid's published database explanation says MDB supplies Media Tool/relink information and on-disk caches can lag. Thus a correct MDB reader establishes recorded database metadata; agreement between readers does not establish that physical media is currently present or unchanged.
