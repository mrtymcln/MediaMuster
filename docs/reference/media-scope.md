# Managed-media scope and format identity

A storage family, file container, coding format and Avid identity answer different
questions. Keep them separate when adding a parser or changing discovery.

| Fact | Meaning |
| --- | --- |
| `Avid MediaFiles/MXF/<folder>` | Managed MXF location; ordinary direct ingest folders are admitted, not only numbered folders. |
| `OMFI MediaFiles` | Separately gated legacy managed-media location; it can contain `.omf`, `.wav` and `.aif`. |
| Header/container | Actual structural format of an opened file. A directory or suffix is a routing hint. |
| Coding identifier | Encoding of the essence, such as DNx, PCM or uncompressed picture; separate from MXF/OMF wrapping. |
| FileMobId / MasterMobId | Avid file/master associations. Copies can share them; they are not physical filesystem identities. |
| `OmfScan` | Folder-family admission flag. It does not prove the actual container or the source of each selected value. |

OMF and MXF are not a before/after-year division. Avid's video and audio format
settings can differ, and both directory families can coexist. PMR/MDB names also
occur in both families. Legacy-looking identifiers can occur inside genuine MXF;
neither ID width nor an old identifier prefix proves an OMF container.

OP-Atom normally stores separately managed essence tracks. The standard permits
multichannel audio on its single essence track; “one audio channel per file” is
a common workflow, not a universal OP-Atom rule. A database-backed scan can
intentionally leave a media header unopened; its database classification is not
independent structural validation of that physical file.

## Supported scope

The current discovery and gates are defined in [release feature gates](../release-feature-gates.md).
Bella supports its bounded OP-Atom MXF and legacy OMF 1/Bento 1.0 paths, with
native WAVE/AIFF support under OMFI admission. UME/OP1a, proxy `.pmxf`, arbitrary
external linked media and SDII are outside current discovery. General MXF
standards describe layouts broader than Bella's initial-header reader.

The Media Composer 26.8.0.58987 arm64 media-extension writer at `0x351bac`
contains legacy branches for `WAVE → .wav`, `AIFF → .aif`, `Sd2f → .sd2`, and
other legacy media → `.omf`; its newer domain selects `.mxf`. This is evidence
that the installed binary retains an SDII filename path, not proof of a current
SDII capture option or MediaMuster support. Avid's 2009 finishing guide describes
legacy SDII playback/export while removing SDII as a selectable project format.

## Primary references

- [Avid audio/video storage settings](https://kb.avid.com/pkb/articles/en_US/troubleshooting/en273303): separate media-creation choices and coexistence of the directory families.
- [Avid Video Satellite Guide](https://resources.avid.com/SupportFiles/attach/Pro_Tools/10.0/ENGLISH/Video_Satellite_Guide.pdf), printed page 34: managed `.omf`, `.wav`, `.aif` and `.mxf` conventions.
- [Avid Pro Tools ISIS Guide](https://resources.avid.com/SupportFiles/attach/Pro_Tools/10.0/ENGLISH/Pro_Tools_ISIS_Guide.pdf), printed page 4: local numbered and shared `client.number` MXF folders.
- [OMF Interchange 2.1](https://www.cubase.it/wp/wp-content/uploads/2014/12/omfspec21.pdf), Appendix B and MDFL/WAVD definitions: 12-byte standard UID and external/raw-media distinctions.
- [SMPTE ST 377-1:2019](https://pub.smpte.org/latest/st377-1/st377-1-2019.pdf), sections 6.6–6.7 and 7.2.1: structural MXF identification; [ST 390 OP-Atom](https://pub.smpte.org/pub/st390/st0390-2011_stable2016.pdf), sections 5 and 8.2.2: zero run-in and essence-track scope.
- [SMPTE ST 330:2011](https://pub.smpte.org/doc/st330/20110823-pub/st0330-2011.pdf), Annex D, and [BBC WHP 155](https://downloads.bbc.co.uk/rd/pubs/whp/whp-pdf-files/WHP155.pdf), page 7: identifier generation and legacy-compatible MXF Package UIDs.
- [Avid Pro Tools 2019.10](https://resources.avid.com/SupportFiles/PT/Whats_New_in_Pro_Tools_2019.10.pdf), page 5: separate SMPTE, Pro Tools UMID-chunk and OMF-chunk identity meanings.
- [Avid database regeneration guidance](https://kb.avid.com/pkb/articles/en_US/Troubleshooting/Refreshing-Media-Databases): PMR/MDB locate managed media and can be regenerated by Media Composer.
- [Avid finishing guide](https://resources.avid.com/SupportFiles/attach/FinishingGuide_4.0.pdf), pages 46–47: SDII legacy limitations.

These sources explain format/storage concepts; they do not publish a complete
PMR/MDB layout or certify all Avid writers. See [compatibility limits](parser-compatibility.md).
