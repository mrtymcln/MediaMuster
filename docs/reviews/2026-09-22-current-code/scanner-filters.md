# Scanner, inventory, filters, volume and CSV review

Reviewed the current checkout read-only on 2026-09-22. Production code was not changed. Probe builds use the current production sources, macOS and Qt 6.5.3. Artifacts are in [evidence/scanner](evidence/scanner/).

## Verified findings

Follow-up, 23 September: the user confirmed quarantine folders are flat. Finding 2 below reproduces only with an artificially nested folder outside the supported layout. Its original fix recommendation is superseded: remove quarantine recursion, retain direct-file warnings and flags, and change nested fixtures to exclusion tests. Existing layout admission helpers already reject nested quarantine paths. Do not add per-child database support. CSV work was deferred by the user.

1. **[P2] CSV export reports success before buffered output is written.** `src/mediacsv.cpp:97-100` (especially line 100). `QTextStream::status()` is evaluated before the stream destructor flushes its pending bytes. A small export can return `true` even when all writes fail, allowing the UI to announce a successful export containing zero bytes. The current-code probe set only its own process's `RLIMIT_FSIZE` soft limit to zero, ignored SIGXFSZ, invoked `MediaCsv::write`, then restored the limit: return value was true, file length was 0. Explicitly flush the stream and file before checking errors; preferably write through `QSaveFile` and check `commit()` so a failed export also preserves an existing destination. Add an injected write/flush failure test; the existing `tests/tst_mediacsv.cpp:173-196` only covers successful files. Confidence: high. Evidence: `probe.cpp`, `probe.log`.

2. **[P2] Recursive quarantine rows borrow the root folder's databases.** `src/mediascanner.cpp:845-846`, with root database load at 768 and recursive enumeration at 795-805. Every file under `Quarantined Files`, including nested files, is passed the same PMR/MDB and folder status. A nested file whose basename occurs in the root PMR is falsely Listed even though no PMR exists in its actual containing folder; database metadata from unrelated same-named root files may also leak into its row. Conversely, actual databases in nested directories are ignored. Current-source fixture probe: copy supplied `msmFMID.pmr`, `msmMMOB.mdb` and tone fixture to quarantine root, then copy the tone into `Old/` without databases. `Old/tone` reports PMR-present=false, status=Listed, project=block 1729. It is consequently excluded from No Database. Process quarantine entries grouped by their actual parent directory, retaining the quarantine flag and logical media folder; key both database passes consistently by actual parent. Add same-name root/child and child-only-database regressions. Confidence: high for observed status error; metadata contamination follows directly from shared inputs. Evidence: `scanner_probe.cpp`, `scanner_probe.log`. Existing `tests/tst_scanner.cpp:2846-2878` verifies recursion/flags but supplies no databases.

3. **[P3] Duration sort can disagree with displayed drop-frame timecode.** `src/mediafilterproxy.cpp:273-288`, especially 282. The comment promises displayed-timecode order, but the key is raw frames / nominal base and ignores drop-frame numbering. Current-source ascending sort places DF 17,982 frames at base 30 (`00;10;00;00`) before NDF 17,990 frames at base 30 (`00:09:59:20`). Define the desired order explicitly. To retain the existing documented display-based policy, share numeric timecode components between rendering and comparison, accounting for DF, and test mixed DF/NDF plus different rates. If actual running time is intended instead, store the exact edit-rate numerator/denominator and document that distinction. Confidence: high. Evidence: `probe.cpp`, `probe.log`; rendering implementation `src/mediafile.h:347-379`.

4. **[P3] Flat table model reports children for valid parents.** `src/mediatablemodel.cpp:11-17`. Both count methods ignore `parent`, returning the whole table's dimensions beneath a valid cell while `QAbstractTableModel::parent()`/`hasChildren()` describe a flat model. With two rows the probe gets rowCount(validParent)=2 and columnCount(validParent)=15. Qt's actual `QAbstractItemModelTester` emits failures at its hasChildren and parent(childIndex) checks. Return zero for valid parents in both methods; attach the model tester to the existing model tests, including reset, remove and feature-column mutations. Confidence: high; no visible current QTableView crash was established. Evidence: `probe.cpp`, `probe.log`.

## Verified mismatch with wider operational impact left to operation review

- `src/pathkey.h:8-11` promises Unicode-form normalization, but lines 43-45/65-72 preserve the leaf without NFC normalization. On the current APFS filesystem, NFC `café.mxf` and NFD `café.mxf` resolve to the same canonical file yet yield different `PathKey::normalise` keys. Confirmed in `probe.log`. The only current product uses are destination keys in `src/oprunner.cpp:1444` and `1534`; root/operation reviewer should determine the resulting Keep Both behavior. Fix the claim even if key semantics deliberately remain platform/filesystem-specific. Do not blindly normalize all filesystem paths on systems where the distinct forms may name distinct files.

## Platform issue established by code, not Windows execution

- **[P2/P3 portability] Non-C: Windows system-drive locations are omitted.** `src/conventions.h:95-96` returns literal C:/ locations, whereas `src/volumemanager.cpp:167-169` skips the actual `%SystemDrive%`. On a Windows installation on D:, its root is skipped and pass 3 never restores D:/ or that installation's Public Documents media location. Resolve actual system drive/public-documents locations using platform APIs, retaining legacy C: locations only as intentional additional probes. Add injectable system-location tests. Logical confidence high; no Windows runtime probe was run here. Current docs intentionally repeat C: at `docs/current-behaviour.md:83-84`, so update docs along with behavior.

Remove the inventory field unless a real product use is planned; parsing the instance may still be needed to isolate the effect/sequence name.
