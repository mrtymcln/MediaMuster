# Bella: Precompute Category from MDB

Research date: 20 October 2026. The user approved the separate
[Type rules](type.md): selected-master usage 1 is Precompute, 7 is Media and
unknown/unreadable Type is displayed/exported blank. **The user approved these
Precompute Category rules on 20 October 2026, including blank unreadable values.
They are not yet implemented.** OldScanner remains active and Bin Filter is
unchanged.

## Meaning and owner

Media Composer derives two precompute groups from the selected master's
metadata: **Rendered Effects** and **Titles and Matte Keys**. Avid documents
both choices in its [Media Tool instructions](https://kb.avid.com/pkb/articles/en_US/Knowledge/How-to-find-clips-in-the-Media-Tool)
and explains their introduction in [What's New for v8.5, page 25](https://resources.avid.com/SupportFiles/attach/WhatsNew_MediaComposer_v8.5.pdf#page=25).
Those documents establish the visible groups; the installed binary establishes
the predicate below. This is a derived classification, not a standard MDB
property containing the category's display name.

Start with the already selected qualified master used for Type, Clip Name and
Original Bin. Only a master already established as Precompute needs this
category test. Audio/video Kind remains the selected physical descriptor's
separate result. These are not effect-palette categories or proof that a
precompute is used by a particular timeline.

For the verified legacy MDB layout:

| Established master facts | Category |
| --- | --- |
| Exact direct `_IMPORTSETTING` object attribute absent | Rendered Effects; track count unnecessary |
| Exact direct `_IMPORTSETTING` object attribute present; at least two direct video tracks | Titles and Matte Keys |
| Same object attribute present; fewer than two direct video tracks | Rendered Effects |
| Decisive attribute/track facts unreadable, conflicting or unsupported | Unavailable; preserve separately proven Precompute Type |

## What Media Composer reads

The native bin-display predicate first checks master role and
AppCode 1. In the installed 26.8.0.58987 arm64 build:

- `brDisplayable` in the main executable (`0x100db5f64`), at
  `0x100db60c0..615c`, calls `GetImportSettingAttrList`. A found object attribute
  and `NumVideoTracks() >= 2` select display bit 11; the defined alternatives
  select bit 6. An absent attribute skips the track count.
- `BinSetDisplayDialog` binds bit 6 to the Rendered Effects checkbox and bit 11
  to the Titles and Matte Keys checkbox. Dialog initialization supplies the
  corresponding visible labels. This connects the predicate to those specific
  groups without claiming every Media Composer column uses the same path.
- `GetImportSettingAttrList` (`libameLibrary`, `0x2ab7c0`) gets the composition's
  own attribute list and searches for exactly `_IMPORTSETTING` as an object
  attribute. `CoreAttrList::FindObject` (`0x6e818`) requests kind 3 through
  `FindAttr` (`0x6cc7c`); the name lookup uses `strcmp`, not a prefix match.
  A wrong-kind entry is not a found object attribute. There is no recursive
  search through nested attributes.
- The found flag is independent of the stored object pointer. A null object
  payload can still count as present. The category predicate does not inspect
  import settings, paths or any contents behind the pointer. Do not require
  recorded Source Path or decode an import-settings body for this category.
- `ATrackGroup::NumVideoTracks` (`0x2197f0`) examines the master's immediate
  track components and counts `GetType() == 1`. It does not recursively count
  nested picture components or sum tracks across related masters/files.

The MDB adapter needs the owner's `OMFI:CPNT:Attributes` relationship, its
direct `ATTR:AttrRefs` entries, and the candidate `ATTB:Name` and typed
`ATTB:Kind`. Kind 3 identifies an object attribute. When present, use
`TRKG:Tracks` to each immediate `TRAK:TrackComponent`, then its own
`CPNT:TrackKind` to count picture tracks. Object references, kind values and
track kinds are typed binary values in the applicable object byte order.
The known attribute key is ASCII; it does not require guessing UTF-8 versus
MacRoman. The result's visible labels are generated by the app.

Actual `ATTB:Kind` is `omfi:AttrKind`, two bytes; direct component TrackKind
is `omfi:TrackType`, two bytes. The observed object references occupy eight
bytes and the reference arrays carry a two-byte count followed by those
references. `_IMPORTSETTING` names occupy 15 bytes including their NUL. These
are observations of the supported little-endian legacy records, not permission
to assume every future MDB has the same container or reference layout.

The native in-memory attribute container enforces unique names. A damaged MDB
with conflicting same-name records is not permission to choose the first
convenient match. An unreadable relevant list is not confirmed absence. Bella's
general MDB structural-damage policy remains a separate review; retain enough
local availability state to avoid inventing a category.

## MDVx

The reviewed MDVx ordinary MDB enrichment path has no separate category value,
column, CSV field or category filter for these two groups. It stores the master
UsageCode and can overwrite it with synthetic `15 / IMPORTED` when an attribute
name starts with `_IMPORTSETTING`. That override does not require Precompute
usage 1, the exact terminated name, object kind 3 or the video-track count.

Consequently, its Imported label cannot supply Bella's Precompute Category.
The observation is scoped to the traced ordinary inventory path; no live
MDVx scan/export or universal absence of unrelated app functionality is claimed.

## Actual databases

A fresh read-only input audit covers all six current MDB/PMR pairs and all
1,340 selected master objects, summed within their individual MDB contexts.
The 135 selected Precompute masters are associated with 171 physical rows:

| Own direct object attribute | Direct track kinds | Distinct Precompute masters, summed by MDB | Physical files | Native-predicate category |
| --- | --- | ---: | ---: | --- |
| Present | Two picture components: 1, 1 | 28 | 64 | Titles and Matte Keys |
| Confirmed absent | One picture component: 1 | 58 | 58 | Rendered Effects |
| Confirmed absent | One sound component: 2 | 49 | 49 | Rendered Effects |
| **Total** | | **135** | **171** | **64 titles/mattes; 107 renders** |

All decisive own attribute/track references in these cases are complete, with
no conflicting exact-name kinds or duplicate exact object entries. All observed
import-object payloads resolve to existing targets; the null-payload case is
established by native found-flag semantics and existing synthetic tests, not
an observed null in this corpus. Ordinary usage-7 controls were also audited;
category work remains gated by separately proven Precompute Type.

Master counts are local-object/identity counts summed by MDB, not globally
deduplicated IDs across copies. A direct track count is not a physical-file
count. The category of an associated master can apply to multiple inventory
rows, including both picture and sound media for renders.

The audit verified 1,037,588 relevant retained property rows against actual
MDB ranges. It uses retained, hashed Bento indexes and independent owner/input
logic. It is not a newly independent entire TOC
decoder and does not use OldScanner classification or physical media headers
as an oracle. These clean current inputs do not exercise damaged category
records, unsupported layouts or absent-master recovery.

[Curated evidence](../../../Project%20Bella/evidence/mdb-precompute-category-2026-10-20.json)
retains source hashes, typed values, representative own attribute/track paths,
native entry points and the MDVx trace. Raw probes, bulk indexes and disassembly
remain outside the repository.

## Current MediaMuster and agreed Bella retention

The current [pure classifier](../../../src/precompute.h) already expresses the
verified decision in a small C++17 function. The
[MDB adapter](../../../src/oldscanner/mediaengine/mdbprojection.cpp#L932)
establishes attribute presence and, only when present, direct video-track count.
It additionally requires complete references and preserves Type when the
subcategory is unavailable. Some completeness checks are broader than this
scalar decision; Bella should validate the relevant owner/list inputs without
building a lasting graph of unrelated properties.

Current `precomputeCategoryDisplay()` shows Rendered Effects, Titles and Matte
Keys or lowercase `unknown` for precomputes; ordinary Media is blank. The
optional precompute feature gate controls the detail columns and controls.
When that feature is enabled, OldScanner can request a media-header read for
missing category. This describes the existing implementation, not a Bella
extra-read requirement. Source precedence and header scheduling are later
decisions.

For Bella, the user agreed:

1. Carry over the verified interpretation and useful tests into a small pure
   helper. Apply it only to the already selected Precompute master. Reuse its
   direct attribute information already needed for retained metadata such as
   Original Bin, rather than searching for another owner.
2. Check the exact direct object attribute without reading its body. If absent,
   return Rendered Effects immediately. Only if present, establish whether
   there are at least two immediate video tracks.
3. Retain a small category enum and necessary availability information. Reuse
   the result for that master's associated physical rows. Release temporary
   attribute/track-reading data after its required consumers finish; do not
   retain an import-settings object graph or formatted label solely for this
   field.
4. Generate the two labels at display/export. Use blank for unavailable
   category and for ordinary Media; an unavailable category must preserve the
   independently established Precompute Type. Blank unavailable category
   changes OldScanner's current lowercase `unknown`, as approved.
   Preserve an explicit Unknown value for the optional category filter. A blank
   table cell must not turn an unknown-category choice into a wildcard; current
   filter paths use empty strings to mean all descendants. Filter presentation
   must remain distinct from the agreed blank table/CSV presentation.
5. Preserve the optional precompute feature and the retained Effect Category
   and Effect requirements. The user later [excluded Effect Sequence](effect-sequence-exclusion.md)
   from Bella's columns and stored data. No guessing from names, codec,
   file usage or import-attribute prefix. The combined title/matte group does
   not identify a particular title tool, matte effect or plug-in.

C++17 scoped enums/value records and a pure conditional are sufficient. Use
pinned Qt 6.5.3 checked typed/endian reads in the source adapter. The current
useful regression cases include absent import, present import with one versus
two video tracks, null object payload, unreadable/wrong-width kind and
preservation of Type. Existing test-source inspection is not a new passing
test run. OMF2 and other object-layout equivalents need their own evidence;
do not assume UserAttributes is the required direct legacy attribute list.

No runtime code changed, no build/tests ran for this research-only review and
no speed or memory improvement is measured.
