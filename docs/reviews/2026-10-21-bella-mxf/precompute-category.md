# Bella: Precompute Category from MXF

Research date: 22 October 2026. **The user approved these MXF Precompute Category
rules on 22 October 2026; they remain unimplemented.** MXF Type is approved separately. OldScanner remains active;
Bin Filter is unchanged. The [MDB category rule](../2026-10-18-bella-mdb/precompute-category.md)
is already approved.

## Meaning and decision

This is a derived group, not a header text property containing the visible
label. Avid documents the groups **Rendered Effects** and **Titles and Matte
Keys** in its [Media Tool instructions](https://kb.avid.com/pkb/articles/en_US/Knowledge/How-to-find-clips-in-the-Media-Tool)
and [v8.5 changes, page 25](https://resources.avid.com/SupportFiles/attach/WhatsNew_MediaComposer_v8.5.pdf#page=25).
The native trace establishes the predicate.

Start only with the same associated master already established as Precompute
under the [agreed MXF Type rules](type.md). Use its own direct attributes and
immediate tracks; no replacement master, recursive import search or physical
file count is needed.

| Established facts in the supported form | Category |
| --- | --- |
| Exact direct `_IMPORTSETTING` object attribute confirmed absent | Rendered Effects; no category track count needed |
| Object attribute present; at least two immediate picture tracks | Titles and Matte Keys |
| Object attribute present; fewer than two immediate picture tracks | Rendered Effects |
| Required facts unreadable, conflicting or unsupported | Unavailable at this source; preserve separately proven Precompute Type |

## Media Composer: predicate and MXF representation

Fresh native functions confirm `brDisplayable` (`0x100db5f64`): after checking
master role and AppCode 1, `0x100db60c0..0x100db615c` tests
`GetImportSettingAttrList` and then `NumVideoTracks() >= 2`. Display bits 6/11
are connected to the two named groups by BinSetDisplayDialog and its labels.
This is a traced bin-display predicate and documented group meaning, not an
observed live GUI classification on these sample files.

`GetImportSettingAttrList` searches the composition's **direct exact-name
object** attribute. A prefix, nested occurrence or a scalar of the same name is
not equivalent. `NumVideoTracks` counts immediate master track components of
native picture kind. The number of physical files, linked tracks to this one
file, nested picture components or related masters is not that count.

MXF represents the relevant object through a TaggedValue wrapper. Fresh
`ConvertAttributesFromAAF` tracing at `0x17a2e8` recognises the string marker
`__AttributeList`, then calls `GetAttributeList` at `0x17a480`. It adds the
native object attribute only after a successful call and non-null list result
(`0x17a484..0x17a4a4`). Therefore the string marker alone is insufficient.
A valid empty nested reference array can still create an object list; missing
or broken wrapper references are not the same as a valid empty list.

The final category predicate does not inspect paths or settings inside that
object. The general native importer constructs attributes elsewhere, but that
broader work does not make every settings value a category input. Bella should
preserve outer wrapper/reference qualification without inventing a new need to
interpret recorded Source Path or settings contents.

Native PortableObject and scalar forms have separate conversion behaviour.
A readable numeric same-name scalar can become a native number attribute,
which is not found by the object-only predicate. Current MediaMuster's MXF
adapter conservatively leaves that form unavailable. This review does not
silently expand its supported indirect-value forms or claim every native
wrong-kind case has identical Bella output.

## What Bella needs from the header

Reuse the qualified master's own `MobAttributeList`. Resolve direct TaggedValue
references, decode their Name and the supported typed Value wrapper. Match
`_IMPORTSETTING` exactly. For the supported object-list form, validate the
outer `TaggedValueAttributeList` array and its references; a valid count-zero
array is different from a missing property. Do not recursively interpret the
settings body's semantics solely to decide category.

TaggedValue names are Unicode strings. Value is an Indirect with its own
recorded type and byte-order context; do not decode every payload as one text
encoding or assume the container's endian rule replaces the Indirect layout.
The output labels are generated by MediaMuster.

If the object is present, use the master's direct Tracks and each immediate
track's own sequence/segment DataDefinition. Honour supported picture, sound
and timecode definition identities and necessary reference qualification.
Count all immediate master picture tracks, including a track pointing to the
other picture/matte file. No other physical media file needs opening to learn
those already recorded track kinds. Duplicate, broken or unsupported decisive
track facts cannot manufacture a category.

## MDVx

Rechecked immutable ordinary MXF wrapper/table/CSV/filter traces and the
installed binary hash. The ordinary MXF wrapper transfers names, Project and
IDs, with no Type/category or direct-track-count publication. The ordinary
inventory has no equivalent two-group Precompute Category result.

MDVx's synthetic IMPORTED value from an `_IMPORTSETTING` name-prefix match is
not this classification: it lacks the selected Precompute gate, exact object
qualification and picture-track test. Do not copy it for Bella's category.
These are bounded ordinary-path findings, not a claim about every raw browser
or bundled library capability; no live app/export ran.

## Current MediaMuster and actual examples

Current [MXF projection](../../../src/oldscanner/mediaengine/mxfprojection.cpp:1234)
already feeds the small [pure category helper](../../../src/precompute.h).
It checks the direct master, typed supported object wrapper and complete outer
references; only then does it count immediate picture tracks. A confirmed
absent object skips category track counting. Type and category are already
separate compact classifications, and master facts are reused for associated
rows. There is no new performance benefit merely from recreating this helper.

Reanalysis of 11 qualified Precompute file/master pairs from the
[bounded Type sample](type.md#actual-header-examples) finds:

| Raw facts | Files | Source-derived category |
| --- | ---: | --- |
| Valid direct object-list wrapper, nine existing child references, two immediate picture tracks | 10 alpha files | Titles and Matte Keys |
| Direct attribute list confirmed absent; one immediate picture track | 1 render file | Rendered Effects |

For each alpha master, **only one of its two picture tracks points to the
physical alpha MXF**. A file-only linked-track count of one would therefore
misclassify it. All 11 source-derived categories agree with the original
same-full-ID/master MDB facts. Two MDB hashes and relevant original byte
ranges were freshly checked; the MXF metadata captures were reused, with no
new MXF read.

These are independent raw interpretations, not newly executed OldScanner
category outputs. The earlier 2,411-file Compression probe did not capture this
field. No actual damaged wrapper, valid-empty wrapper, scalar, PortableObject,
duplicate attribute or unreadable-track specimen was present in this sample.
Native/source evidence covers some separate cases; no new passing regression
run or universal category coverage is claimed.

## Agreed Bella retention

1. Preserve the proven predicate in a small new pure helper. Reuse the same
   selected Precompute master's direct facts already needed by retained fields;
   do not search another owner for a preferred category.
2. Keep the supported MXF wrapper/reference qualification. Do not equate a
   marker alone, failed read, unknown indirect type or missing wrapper array
   with a usable object or confirmed absence. Preserve the current conservative
   unsupported scalar/PortableObject handling unless separately expanded.
3. When object absence is established, return Rendered Effects without category
   track counting. When present, establish the immediate picture-track threshold
   with the supported typed references/DataDefinitions. Keep physical file
   association and total immediate master track count distinct.
4. Retain a small RenderedEffects/TitlesAndMatteKeys/Unknown enum and necessary
   availability/origin information. Release temporary attribute/track data
   after all consumers finish; keep no full import-settings body or formatted
   label solely for category.
5. Generate the current two labels at display/export. Ordinary Media and
   unavailable category are blank; independently proven Precompute Type stays.
   Preserve an explicit Unknown category for the optional filter, separate from
   a blank table cell or the filter's all-descendants choice, as agreed for MDB.
6. Preserve optional precompute details and the existing Effect Category/Effect
   requirements. Effect Sequence stays excluded. No new source priority or
   extra-header-opening rule is authorised by this approval.

C++17 enums/value records and checked Qt 6.5.3 source decoding are sufficient.
The useful improvement is compact source extraction around preserved semantics;
no speed/memory gain is measured and no new framework is needed.

[Curated evidence](../../../Project%20Bella/evidence/mxf-precompute-category-2026-10-22.json)
retains native functions/hashes, the 11 raw owner-qualified comparisons, current
source/test references and the MDVx route boundaries. No runtime files changed,
app/private APIs ran, or new tests/builds/benchmarks were executed.
